# Specification Amendment A-001: Process-Tiered Instance Architecture

**Amendment ID:** A-001  
**Date:** 2026-10-23  
**Status:** PROPOSED (Pending formal adoption)  
**Affects:** docs/spec/ (Parts 5.1, 5.2, 6.1, 7.1, 7.3, 7.5)  
**Architectural Origin:** Decision D-008, SPIKE-005 findings, VERIFY-S-022 runtime tests  

---

## 1. Summary of Architectural Realignment

The master blueprint originally assumed a single Gecko process with fine-grained per-tab preferences for the Surface (S) and Network (N) axes. Runtime evaluation on Firefox ESR 153.5.1esr proved that:
1. Core security preferences (`javascript.options.baselinejit`, `ion`, `wasm`, `webgl.disabled`) are **process-wide globals** within the Gecko runtime and SpiderMonkey compiler.
2. Background browser networking (OCSP, captive portal, extension updates) and WebRTC can leak outside container-based Tor SOCKS proxies when sharing a single socket process.

Amendment A-001 amends the specification to adopt a **Process-Tiered Architecture**, wherein security levels are enforced via dedicated, isolated process instances managed by a local orchestrator.

---

## 2. Proposed Amendments by Spec Part

### 2.1 Amendment to Part 5.1: The Three Axes & Tier Bundles

**Current Text Concept:** Every Cell independently selects any combination of `{N, S, I}`.  
**Amended Text:**
> A **Tier** is a bundle of instance-wide engine settings across the Surface (S), Identity (I), and Network (N) axes. Because compiler, sandbox, and proxy controls operate at the process level in the Gecko engine, concurrent Cells with different attack-surface requirements run in separate process instances.
>
> Aegis defines **four canonical named tiers (presets)**:
> 1. **Standard Tier (S1 / I1 / N0):** Everyday browsing. JIT and WebAssembly enabled; first-party cookie partitioning (dFPI); direct routing.
> 2. **Guarded / Strict Tier (S2–S3 / I2 / N1):** Hardened browsing. HTTPS-only mode; strict DoH/DoT; audio autoplay blocked; S3 sub-tier locks JIT and WebAssembly off.
> 3. **Research / Tor Tier (S3 / I2 / N2):** Three-hop onion routed circuit with remote DNS; WebRTC locked off; JIT/WASM locked off; container storage isolation.
> 4. **Detonation Tier (S4 / I4 / N2 or N1):** Static document mode; all JavaScript execution disabled; remote fonts disabled; ephemeral RAM-only profile.
>
> **Mapping and Rejection of Custom Combinations:**
> - Arbitrary custom combinations requested by users or modules cannot spawn arbitrary processes.
> - Any custom combination must **map up to the nearest stricter tier** (e.g. requesting `{N0, S3, I1}` maps up to the S3 Strict tier; requesting `{N2, S1, I1}` is rejected or promoted to Research/Tor with I2).
> - Conflicting combinations (e.g., requesting N2 Tor routing while demanding JIT compilation or unpartitioned storage) are **strictly rejected with a visible explanation**.

### 2.2 Amendment to Part 5.2: Axis S (Surface Levels)

**Amended Text:**
> S-levels S1 through S4 are bound to dedicated instance processes:
> - **S1 & S2:** Run in the primary browsing instance. Controlled via declarative policy and autoconfig.
> - **S3:** Runs in a dedicated hardened instance launched with `AEGIS_SURFACE_TIER=S3`. `aegis.cfg` dynamically executes `lockPref()` on `javascript.options.baselinejit`, `ion`, `wasm`, and `webgl.disabled`.
> - **S4:** Runs in the detonation instance launched with `AEGIS_SURFACE_TIER=S4`. In addition to S3 locks, `javascript.enabled` and `gfx.downloadable_fonts.enabled` are locked to `false`.
> - **Fail-Closed Rule:** If an instance launches without a valid launcher authorization token or with a mismatched tier token, `aegis.cfg` automatically fails closed to S4 minimal surface.

### 2.3 Amendment to Part 6.1: Cells and Anchored Cells

**Amended Text:**
> - Cells are assigned to the appropriate process tier based on their declared policy.
> - Within a given process tier, Multi-Account Containers (`cookieStoreId`) provide client-side storage, cookie, localStorage, IndexedDB, and cache isolation between Cells sharing that tier.
> - **Anchored Cells (e.g., Banking, Work):** Open in a dedicated profile directory or dedicated container within the Guarded/Strict tier (minimum S2/I2, extensions restricted).
> - Tabs belonging to different tiers exist in separate OS windows coordinated by the Aegis shell and Command Palette (M2).

### 2.4 Amendment to Part 7.1: Link Guard Escalation

**Amended Text:**
> - Because a running Gecko process cannot safely de-optimize or strip JIT/WASM compilation mid-session for an existing tab, **automatic Link Guard escalation is implemented via Inter-Process URL Hand-Off**.
> - When Link Guard detects high-risk phishing, credential harvesting, or brand impersonation signals that mandate escalating a page to S3 or S4:
>   1. The originating instance suspends navigation and displays an interstitial warning.
>   2. If the user proceeds (or if automatic policy triggers), the URL is passed via authenticated local IPC to the **stricter instance tier** (e.g. Detonation S4).
>   3. The page opens inside the isolated, script-disabled environment with the originating context severed.

### 2.5 Amendment to Part 7.3: API Tripwires

**Amended Text:**
> - Tripwires instrument high-entropy, hardware, and permission APIs within each instance.
> - When a tripwire triggers (e.g., unexpected audio canvas readback, clipboard command lure), the event is dispatched from the instance extension via local IPC to the central Aegis Trust Ledger.
> - Ledger entries aggregate across all running instances into a single unified posture ledger.

### 2.6 Amendment to Part 7.5: Shared Flight Recorder

**Amended Text:**
> - The Flight Recorder operates as a unified service across all instances.
> - Rather than fragmented, per-instance logs, instances stream structured event envelopes (redacted URLs, TLS parameters, verdicts, tripwires) to a local Unix socket managed by the orchestrator.
> - The orchestrator appends events to a single **monotonic, tamper-evident hash chain**:
>   $$\text{Hash}_i = \text{SHA-256}(\text{Hash}_{i-1} \parallel \text{Event}_i)$$
> - A compromised renderer in one tier cannot forge or truncate the hash chain of prior events across other instances.

## 3. Impact Assessment

* **Security:** Significant increase in attack surface reduction. S3/S4 JIT/WASM disablement is enforced at the OS process boundary; Tor traffic cannot leak into cleartext socket processes.
* **Memory Cost:** Measured empirically at ~550–600 MB RSS per active tier with realistic multi-tab workloads. 2 active tiers consume ~1.1–1.2 GB RAM (comfortably within available system resources).
* **Codebase Maintenance:** Minimizes Gecko engine patches by utilizing Mozilla's supported autoconfig and enterprise profile features.
